# Domain docs

This repository uses a single-context layout:
`GLOSSARY.md` at the root and architecture decisions under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and any ADRs relevant to the area being explored.

If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses and test names.
If a needed concept is missing, reconsider the terminology or note the
gap for domain-modeling.

## Decisions

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR number and the reason to reopen the decision.
